## Diagnosis
Root cause: The six delivery fields are plain `mutableStateOf` properties on `CheckoutViewModel`, whose only constructor takes no arguments and has no `SavedStateHandle` (CheckoutViewModel.kt:15-21). The composable reads and writes them directly (CheckoutScreen.kt:34, 67-72). When Android kills the process in the background, the ViewModel is discarded with it. On relaunch, `viewModel()` builds a new empty instance, so every field is blank and Place order stays disabled (CheckoutScreen.kt:82). Nothing in the design persists the input outside process memory.
Fix approach: Give CheckoutViewModel a SavedStateHandle constructor parameter and back each field with it, for example `var name by savedStateHandle.saveable { mutableStateOf("") }` using the lifecycle-viewmodel-savedstate compose helper. The values then survive process death and are restored into the new ViewModel automatically. Keep the existing `viewModel()` call in CheckoutScreen, since the default factory supplies the SavedStateHandle. Optionally keep orderId and error out of the saved state, since they are transient.
Evidence: app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:15 - `class CheckoutViewModel : ViewModel()` has no SavedStateHandle, so nothing can be persisted; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:16-21 - the six form fields are plain `mutableStateOf("")` held in process memory only; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:23-27 - placing, orderId and error are also plain in-memory state; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:34 - `vm: CheckoutViewModel = viewModel()` recreates an empty ViewModel after the process is killed; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:67-72 - each OutlinedTextField is bound to the ViewModel field, so the blank restored state shows up as empty inputs; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:82 - Place order is enabled only when `vm.isComplete`, so the lost fields block the user from submitting
