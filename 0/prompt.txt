droid-monkey attacked this Android app with a real-world fault and it failed. Fix the root cause.

## What happened
Attack `process_death` (process_death): Fill the screen's form, let Android kill the app in the background, then come back to it.
Steps: [{"fill": true}, {"fault": "kill_in_background"}, {"fault": "relaunch"}, {"settle": 6}]
Result: lost_state: 6 of 6 filled fields changed or emptied
Fields lost (before -> after): {'field_name': ['Ravi Kumar', ''], 'field_email': ['ravi@example.com', ''], 'field_phone': ['9876543210', ''], 'field_address': ['12 MG Road', ''], 'field_city': ['Bengaluru', ''], 'field_pincode': ['560001', '']}

## Diagnosis
Root cause: CheckoutViewModel stores all six form fields as plain mutableStateOf properties (CheckoutViewModel.kt:17-22). That state lives only in the in-memory ViewModel, and nothing persists it to a SavedStateHandle or saveable state. When Android kills the process in the background and the user relaunches, the ViewModel is recreated empty, so every field comes back blank. The only saved state in the app is the route in MainActivity (MainActivity.kt:62), and the checkout form was never added to it.
Fix approach: Inject SavedStateHandle into CheckoutViewModel and back each field with it. Seed each mutableStateOf from handle[key] and write every change back to the handle, so the values survive process death. The viewModel() factory supplies the handle automatically, and CheckoutScreen.kt keeps the same property names, so no UI change is needed. Keep the optional scope parameter so existing tests still compile.
Evidence: app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:14 - ViewModel constructor takes only an optional CoroutineScope, with no SavedStateHandle; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:17-22 - the six form fields are plain mutableStateOf values, not persisted anywhere; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:34 - vm defaults to viewModel(), so after process death a fresh empty ViewModel is created; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:67-72 - each CheckoutField is bound directly to vm.name..vm.pincode, so the UI shows whatever the ViewModel holds, which is empty after restore; app/src/main/java/com/shubhasai/monkeymart/MainActivity.kt:62 - the only rememberSaveable state is the route; the checkout form is not saved
