## Diagnosis
Root cause: OrderRepository.submit throws IOException when there is no active internet capability (OrderRepository.kt:27). CheckoutViewModel.placeOrder sets placing=true (CheckoutViewModel.kt:30) and calls orders.submit inside viewModelScope.launch with no try/catch (CheckoutViewModel.kt:31-32), so the exception escapes the coroutine and kills the app. Even if it were caught, placing=false (line 33) is skipped, so the button would stay in its spinner state with no error shown. The ViewModel treats a recoverable connectivity failure as fatal.
Fix approach: In CheckoutViewModel, wrap the submit call in try/catch(IOException) inside viewModelScope.launch, and reset placing in a finally block. Expose the failure as an observable error state (for example, `var error: String?`) that the form renders as a message, with the Place order button re-enabled so the user can retry once the network returns. Do not rethrow, and do not let the exception leave the coroutine.
Evidence: app/src/main/java/com/shubhasai/monkeymart/data/OrderRepository.kt:27 - throws IOException when isOnline() is false, with no retry or fallback; app/src/main/java/com/shubhasai/monkeymart/data/OrderRepository.kt:32-35 - isOnline checks the active network's INTERNET capability; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:30 - placing is set to true before the network call; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:31-32 - viewModelScope.launch calls orders.submit with no try/catch, so the IOException is uncaught; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:33 - placing=false is only reached on success, so a failure leaves the spinner stuck; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:77 - the Place order onClick invokes vm.placeOrder directly with no error handling; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:81 - the button shows the placing spinner whenever vm.placing is true, so a stuck flag is visible to the user
