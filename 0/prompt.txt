## Diagnosis
Root cause: OrderRepository.submit throws IOException when there is no network (OrderRepository.kt:27). CheckoutViewModel.placeOrder launches that call in viewModelScope with no try/catch (CheckoutViewModel.kt:31-34), so the exception escapes the coroutine and crashes the app. Even if it were caught, `placing = true` is only reset on the success path (line 33), so the spinner would stay on forever. The design flaw is that the ViewModel treats a recoverable network failure as an unrecoverable exception and has no error state for the UI to show.
Fix approach: In placeOrder, wrap the submit call in try/catch(IOException) inside the coroutine. On failure, reset `placing` to false and set an observable `error` state (for example 'No network, try again'). Show that error in CheckoutScreen and keep the form contents so the user can retry the button. To make this testable, put OrderRepository behind a small interface (or pass a suspend lambda) so the ViewModel can be tested with a fake that throws.
Evidence: app/src/main/java/com/shubhasai/monkeymart/data/OrderRepository.kt:27 - submit() throws IOException when isOnline() is false, which is the crash site; app/src/main/java/com/shubhasai/monkeymart/data/OrderRepository.kt:32-35 - isOnline() reads the active network capability, so offline always returns false; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:30 - placing is set to true before the launch; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:31-34 - viewModelScope.launch calls orders.submit with no try/catch, so the IOException is uncaught; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:33 - placing=false runs only after a successful submit, so a failure would leave the spinner stuck; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:77 - the Place order onClick calls vm.placeOrder, which is the entry point in the crash stack; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:78-81 - the button is disabled while placing and shows a spinner, and no error is rendered anywhere
