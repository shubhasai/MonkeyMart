droid-monkey attacked this Android app with a real-world fault and it failed. Fix the root cause.

## What happened
Attack `performance` (performance): Load the CPU like a busy mid-range phone, then scroll the screen and use its slowest action; the UI must never freeze.
Steps: [{"fault": "cpu_stress", "threads": 4}, {"scroll": "down"}, {"scroll": "up"}, {"tap": "product_1"}, {"settle": 8.0}]
Result: froze: 1 frozen frame(s) over 700 ms and 3 slow UI-thread frames (p99 53 ms): something blocks the main thread

## Diagnosis
Root cause: The row's clickable lambda calls Thread.sleep(1500) on the UI thread before invoking onProductClick (ShopScreen.kt:56). Compose dispatches the tap on the main thread, so every tap parks the thread for 1.5 s and the input event cannot finish. Under the cpu_stress fault the already-busy CPU makes the block longer and the main-thread frame exceeds 700 ms. The shop list has no reason to wait before navigating, and the detail screen already handles slow loading through its own ViewModel path (ProductRepository.byId, a 5 s delay, ProductRepository.kt:37).
Fix approach: Remove the Thread.sleep from the clickable lambda so it only calls onProductClick(product.id) right away. Any intended latency belongs off the main thread, in the ViewModel or repository (suspend calls in a coroutine scope). The detail screen should show its own loading state while byId runs. Keep the click handler non-blocking so input dispatch returns immediately.
Evidence: app/src/main/java/com/shubhasai/monkeymart/ui/ShopScreen.kt:56 - .clickable { Thread.sleep(1500); onProductClick(product.id) } blocks the main thread on every row tap; Perfetto: long main-thread slice 'dispatchInputEvent MotionEvent UP ... deliverInputEvent' 1501 ms, of which sleeping/blocked 1500 ms, running 1 ms. This matches the 1500 ms sleep inside the click lambda; Perfetto: main thread sleeping/blocked 95% of the trace, and 1 frozen frame over 700 ms, which is the tap on product_1; app/src/main/java/com/shubhasai/monkeymart/data/ProductRepository.kt:37 - byId is a suspend function with delay(5_000), so detail loading is already meant to be async and off the click path
