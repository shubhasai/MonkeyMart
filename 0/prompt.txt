## Diagnosis
Root cause: The coupon scanner decides whether it may open the camera from a persisted SharedPreferences flag, `camera_granted`, that is set to true once and never cleared (CouponScanner.kt:33-38). The button's onClick at CouponScanner.kt:76-77 trusts that flag and calls `CouponScanner.open` directly, which calls `CameraManager.openCamera` at line 44 with no permission check. When the user revokes CAMERA in Settings, the process restarts, the stale flag still says true, and the open call throws SecurityException. The design error is caching a runtime permission state instead of asking the system at the moment of use.
Fix approach: Drop the SharedPreferences flag. In the onClick, check `ContextCompat.checkSelfPermission(context, CAMERA)` at use time and only call `open` when it returns GRANTED; otherwise launch the permission request. Also wrap the `openCamera` call in a try/catch for SecurityException and surface a status message, so a revocation that happens between the check and the open does not crash the app.
Evidence: app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:31-38 - the 'camera_granted' SharedPreferences flag is written to true on grant and read back as the access check; nothing clears it or re-checks the live permission; app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:76-77 - onClick opens the camera whenever the cached flag is true, without checking the permission; app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:43-44 - cameraIdList and openCamera run with no permission check; this is where the SecurityException is thrown after revocation; app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:64-67 - the only place the flag is set, in the permission-result callback, so it is never reset when the permission is later revoked; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:74 - ScanCouponButton is the only entry point to the scanner on the checkout form
