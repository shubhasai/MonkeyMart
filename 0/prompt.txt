## Diagnosis
Root cause: DealLoader.load launches on GlobalScope (DetailScreen.kt:58), so the coroutine outlives the composition and is never cancelled. It captures the Activity's supportFragmentManager (line 57 parameter, used at line 64). The attack taps product_1, waits 1.2s, then rotates. The coroutine is still suspended in ProductRepository.byId (line 59). Rotation destroys the old Activity and its FragmentManager, so when the coroutine resumes, show() at line 64 runs on a destroyed FragmentManager and throws. The design mistake is an unscoped coroutine holding a stale Activity-level UI handle.
Fix approach: Remove GlobalScope and the static DealLoader. Run the product load in the DetailScreen LaunchedEffect(productId), which is cancelled when the composition leaves on rotation, so a stale coroutine can never reach show(). Show the deal dialog from the current, live FragmentManager (or hold the deal as Compose state and render it in-composition) instead of capturing the Activity in a long-lived closure. Keep the product in rememberSaveable or reload it by productId after recreation.
Evidence: app/src/main/java/com/shubhasai/monkeymart/ui/DetailScreen.kt:57 - DealLoader.load takes the Activity and a callback, so the caller's Activity is captured by the work; app/src/main/java/com/shubhasai/monkeymart/ui/DetailScreen.kt:58 - GlobalScope.launch(Dispatchers.Main) creates a coroutine with no lifecycle or composition scope, so rotation does not cancel it; app/src/main/java/com/shubhasai/monkeymart/ui/DetailScreen.kt:59 - ProductRepository.byId suspends here, so the coroutine is still pending when the rotation happens; app/src/main/java/com/shubhasai/monkeymart/ui/DetailScreen.kt:64 - activity.supportFragmentManager.show() runs after the suspension, on the Activity from before the rotation, which throws the reported crash; app/src/main/java/com/shubhasai/monkeymart/ui/DetailScreen.kt:74-75 - DetailScreen calls DealLoader.load inside LaunchedEffect, but the GlobalScope launch inside load means the effect's cancellation never reaches the coroutine; app/src/main/java/com/shubhasai/monkeymart/MainActivity.kt:33-34 - rotation recreates MainActivity and recomposes, so the old Activity's FragmentManager is the one destroyed
