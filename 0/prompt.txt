## Diagnosis
Root cause: CheckoutViewModel.placeOrder sets `placing = true` and launches `orders.submit(...)` in viewModelScope with no try/catch (CheckoutViewModel.kt:30-34). When the network is down, OrderRepository.submit throws IOException at its offline check (OrderRepository.kt:27, using the connectivity check at :32-35). The exception escapes the coroutine, so it crashes the app. Even if it were caught, `placing` would never be reset, so the Place order button would keep showing its spinner (CheckoutScreen.kt:78-81) and the user would get no feedback. The design flaw is that the ViewModel treats a recoverable connectivity failure as an unrecoverable programming error.
Fix approach: In CheckoutViewModel, wrap the submit call in try/catch (CancellationException rethrown), and in finally set `placing = false`. Store the failure in a new observable `error` state, for example a message string, and clear it when placeOrder starts again. In CheckoutScreen, show that error (a Text or Snackbar with a retry hint) so the user knows the order was not placed. Optionally add a `fun interface`/interface for OrderRepository so the ViewModel can be unit tested with a throwing fake.
Evidence: app/src/main/java/com/shubhasai/monkeymart/data/OrderRepository.kt:27 - submit throws IOException when isOnline() is false; this is the crash site; app/src/main/java/com/shubhasai/monkeymart/data/OrderRepository.kt:32-35 - isOnline checks the active network's INTERNET capability; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:30 - placing is set to true before the network call; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:31-34 - viewModelScope.launch calls submit with no try/catch and resets placing only on success; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:32 - the frame where the IOException reaches the coroutine (verdict stack); app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:77-81 - the Place order onClick and the button's spinner, which is driven by vm.placing and would stay stuck
