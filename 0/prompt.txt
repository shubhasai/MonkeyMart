## What happened
Attack `process_death` (process_death): Fill the screen's form, let Android kill the app in the background, then come back to it.
Steps: [{"fill": true}, {"fault": "kill_in_background"}, {"fault": "relaunch"}, {"settle": 6}]
Result: lost_state: 6 of 6 filled fields changed or emptied
Fields lost (before -> after): {'field_name': ['Ravi Kumar', ''], 'field_email': ['ravi@example.com', ''], 'field_phone': ['9876543210', ''], 'field_address': ['12 MG Road', ''], 'field_city': ['Bengaluru', ''], 'field_pincode': ['560001', '']}

## Diagnosis
Root cause: The checkout form's six fields are plain `mutableStateOf` properties on `CheckoutViewModel` (CheckoutViewModel.kt:14-19), and the ViewModel has no `SavedStateHandle` or any other persistence. CheckoutScreen binds each field directly to `vm.name`, `vm.email`, etc. (CheckoutScreen.kt:67-72). When Android kills the process in the background, the ViewModel and its in-memory state are destroyed. On relaunch, the route is restored via `rememberSaveable` (MainActivity.kt:62), so the user lands back on Checkout, but `viewModel()` creates a fresh `CheckoutViewModel` with every field blank. The route survives process death, but the form data does not.
Fix approach: Back the form state with `SavedStateHandle`: take `SavedStateHandle` in the ViewModel constructor and implement each field as `savedStateHandle.getStateFlow` or `savedStateHandle.mutableStateOf` (for example `var name by savedStateHandle.saveable { mutableStateOf("") }` from `androidx.compose.runtime.saveable`), so values are written to the saved-state bundle and restored after process death. The default `viewModel()` factory supplies a SavedStateHandle automatically, so the call site can stay unchanged. Alternatively, use `rememberSaveable` for each field in the composable, but the ViewModel approach keeps the state alongside the placeOrder logic.
Evidence: app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:13-19 - ViewModel with no constructor arguments; six fields stored as plain mutableStateOf with no saved-state backing; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:1-10 - no SavedStateHandle import or usage anywhere in the ViewModel; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:34 - `vm: CheckoutViewModel = viewModel()` creates a fresh ViewModel with default state when the process is restored; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:67-72 - each OutlinedTextField is bound directly to a ViewModel property, so the UI shows whatever the ViewModel holds, which is blank after restore; app/src/main/java/com/shubhasai/monkeymart/MainActivity.kt:62 - the route is saved with rememberSaveable, so the user returns to the checkout screen but the form data is not restored; app/src/main/java/com/shubhasai/monkeymart/MainActivity.kt:80 - CheckoutScreen is reached via the restored route, confirming the screen comes back while its state is lost
