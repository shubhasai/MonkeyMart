## Diagnosis
Root cause: The app records camera consent in a SharedPreferences boolean (`camera_granted`) once the permission is granted (CouponScanner.kt:36-38, 66) and never re-checks the real runtime permission. `hasCameraAccess` (CouponScanner.kt:33-34) reads only that flag, so after Settings revokes CAMERA the button's onClick (CouponScanner.kt:76-77) skips the permission request and calls `open()` directly. `open()` calls `cameras.openCamera` (CouponScanner.kt:44) with no permission check and no exception handling, so the framework throws SecurityException on the main thread and the app crashes. The `@SuppressLint("MissingPermission")` on line 40 hides the missing check from the compiler.
Fix approach: Drop the persisted flag and check the live grant with ContextCompat.checkSelfPermission(context, Manifest.permission.CAMERA) == PERMISSION_GRANTED in the button's onClick. Launch the RequestPermission contract only when it is not granted. Also wrap cameras.openCamera in try/catch for SecurityException (and CameraAccessException) and report the failure through onResult, so a revoke between the check and the open cannot crash the app.
Evidence: app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:33-34 - hasCameraAccess reads only a SharedPreferences boolean, not the runtime permission; app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:36-38 - rememberCameraGranted persists 'camera_granted=true' and nothing clears it; app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:40-44 - open() is annotated MissingPermission and calls openCamera with no checkSelfPermission and no try/catch; app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:64-67 - the permission launcher is the only place the flag is set, after a grant; app/src/main/java/com/shubhasai/monkeymart/ui/CouponScanner.kt:76-77 - the button opens the camera directly whenever the stale flag is true, so the permission prompt is skipped after revoke; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:74 - ScanCouponButton is embedded in the checkout form, which is the screen the attack reached
