## Diagnosis
Root cause: The clickable modifier on each shop row runs `Thread.sleep(7000)` on the main thread before calling `onProductClick` (ShopScreen.kt:56). Each tap therefore blocks the UI thread for 7 s. Under cpu_stress the input dispatch waits on that handler, so the next key/motion event times out at 5 s and Android reports an ANR. The trace matches: a 7001 ms `dispatchInputEvent MotionEvent UP` slice on the main thread, about 7000 ms of it in sleeping/blocked state, and the ANR stack top at ShopScreen.kt:56.
Fix approach: Remove the blocking call from the click lambda so it only forwards the navigation event: `.clickable { onProductClick(product.id) }`. If the 7 s wait stands in for real work (a fetch or validation before opening detail), move that work off the main thread into a coroutine on Dispatchers.IO, for example in a ViewModel or a `rememberCoroutineScope`, and navigate when it completes. Show a loading state in the meantime rather than freezing input.
Evidence: app/src/main/java/com/shubhasai/monkeymart/ui/ShopScreen.kt:56 - `.clickable { Thread.sleep(7000); onProductClick(product.id) }` blocks the main thread inside the click handler; app/src/main/java/com/shubhasai/monkeymart/ui/ShopScreen.kt:56 - the ANR stack's topmost app frame is this same line, ShopScreenKt$ShopScreen$4$1$2$1$1.invoke; Perfetto: `dispatchInputEvent MotionEvent UP` on the main thread (tid 25421, asai.monkeymart) lasts 7001 ms, and its main-thread state is sleeping/blocked for 7000 ms, matching the 7000 ms sleep; Perfetto: the main thread is sleeping/blocked for 22502 ms (92%) of the trace, which is the stalled input pipeline; the CPU stress itself accounts for only the 920 ms + 480 ms of waiting for CPU
