## Diagnosis
Root cause: OrderRepository.submit throws IOException when the active network has no INTERNET capability (OrderRepository.kt:27). CheckoutViewModel.placeOrder launches that call in viewModelScope with no try/catch (CheckoutViewModel.kt:31-34), so the exception escapes the coroutine and kills the app. Even if it were caught, `placing` is only reset on the success path (line 33), so the button would stay in the spinner state with no message. The design gap is that a recoverable network failure is treated as a programmer error, and the ViewModel has no failure state for the UI to show.
Fix approach: In CheckoutViewModel, wrap orders.submit in try/catch(IOException) inside the launched coroutine. Store the failure in an observable `error` state and always reset `placing` in a finally block. CheckoutScreen should render that error as a message with a retry path, and keep the form values, which already survive in the ViewModel. Optionally, inject the repository or submit function so the ViewModel can be tested without a Context.
Evidence: app/src/main/java/com/shubhasai/monkeymart/data/OrderRepository.kt:27 - submit throws IOException when isOnline() is false; app/src/main/java/com/shubhasai/monkeymart/data/OrderRepository.kt:32-35 - isOnline checks activeNetwork INTERNET capability, so a network drop reaches the throw; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:31-34 - viewModelScope.launch calls orders.submit with no try/catch; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutViewModel.kt:30,33 - placing is set true before submit and reset only after success; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:76-78 - the Place order button calls vm.placeOrder with no error handling and no failure state rendered; app/src/main/java/com/shubhasai/monkeymart/ui/CheckoutScreen.kt:38 - OrderRepository is created in the composable with remember, so it is not injected or testable
